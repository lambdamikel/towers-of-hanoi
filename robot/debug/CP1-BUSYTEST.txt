#
# CP1 BUSY-INPUT TEST -- read Port 1 pin 1 and show it.
# Debugging aid for the Hanoi robot protocol.
#
# Purpose: directly probe the INPUT path -- the BUSY line the real program polls
# with `pie 16.001`. This is THE untested assumption (see CLAUDE.md): does a CP1
# Port-1 read actually return 0/1 for pin 1, and with what polarity?
#
# The emulator shows the real program freezes iff this read comes back as 1 while
# the Mega is driving BUSY low. This test lets you watch that read on the CP1's
# OWN display, live, while you toggle the Mega's BUSY with the sniffer.
#
# Loop:
#   - read Port 1 pin 1 (BUSY) into the accu
#   - ANZ it: the CP1 display shows 0 or 1
#   - also mirror it onto D0 (Port 2 pin 1) so the sniffer can confirm
#   - short delay, repeat
#
# How to use:
#   1. Load this; run the Mega with debug/cp1_sniffer.
#   2. Start at 000. Read the CP1 display.
#   3. In the sniffer type 'l' (BUSY low) then 'h' (BUSY high).
#      EXPECTED (assumption correct):  display 0 when you drive low, 1 when high.
#      IF display stays 1 even on 'l'  -> input floats / wrong pin / inverted:
#         that is exactly what freezes the real program in its first busy-poll.
#      IF display never changes at all -> P1E operand/pin-map is not what we think
#         (consult the CP1 manual for the Port-1 read semantics).

000 pie 16.001      # accu <- Port 1 pin 1  (BUSY)
001 anz 02.000      # show it on the CP1 display (0 or 1)
002 p2a 18.001      # mirror to D0 so the sniffer sees it too
003 vzg 03.255      # brief delay
004 vzg 03.255
005 spu 09.000      # loop forever
